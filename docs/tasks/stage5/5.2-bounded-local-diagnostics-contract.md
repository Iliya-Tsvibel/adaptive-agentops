## Objective and proposed change

Provide one opt-in pure function, `format_local_diagnostic(result: Result) -> str`,
in the existing offline reconciliation module. It returns one compact JSON
object for a caller that already holds a Stage 5.1 synthetic projector
result. This slice helps a caller identify the classification, source
availability, and whether the projector attributed a simulated effect
to either source. No logger, sink, registry, or background collector is
part of the function. Existing fixture analysis and output APIs keep
their current behavior.

The implementation allowlist is
`adaptive_agentops/offline_reconciliation.py`,
`tests/test_offline_reconciliation.py`, this contract, and
`docs/campaigns/stage5-progress.md`. The fixture manifest stays frozen.
The scope excludes runtime instrumentation, database or snapshot access,
IPC, CLI, dependencies, persistence, network calls and native dispatches.

## Output and security boundary

Schema version 1 has exactly these keys in this order:

| Key | Allowed values |
| --- | --- |
| `version` | Integer 1 |
| `status` | One existing Stage 5.1 classification, or `UNRECOGNIZED` |
| `controller_coverage`, `target_coverage` | `COMPLETE`, `PARTIAL`, `UNAVAILABLE`, `INVALID` or `null` |
| `effect_sources` | A deduplicated subset of `CONTROLLER` and `TARGET`, in that order |

Require an exact `Result` instance and reject other input types with a
constant error message. At the output boundary validate individual field
types and values against fixed allowlists. A malformed field, including
one introduced through unchecked model construction, yields a fixed
`UNRECOGNIZED` object with null coverages and an empty source list. A
recognized non-effect status always emits an empty source list. Inspect
at most two source entries, and reject larger containers before walking
them. Serialize only reconstructed values, as ASCII compact JSON with
no newline, at most 256 bytes. Inputs are never modified.

The disclosure allowlist excludes reason strings, capture labels,
observation order, effect numbers, identifiers, input bytes, timestamps
and exception text. Diagnostics describe a synthetic projection only.
Callers cannot use them to establish authorization, audit durability,
delivery, non-execution or retry eligibility. Preserve Stage 4 evidence,
principal boundaries and all Controller and Target behavior.
