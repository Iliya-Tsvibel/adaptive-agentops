# Stage 4.2 — Scoped proposal admission

The approved slice demonstrates admission of a single proposal type on the
Control Plane. The only eligible scope is `mock.get_health` for `demo-api` in
`local-mock`. The result is a proposal verdict. Health reads, pending actions,
approvals, dispatch, target traffic, and legacy HTTP are outside the slice.

## Authority and transport

Protected launch configuration supplies the Stage 4.1 endpoint and distinct
service UIDs. A trusted acceptance fixture can explicitly initialize one
immutable grant before the listener opens. Fixture issuance is session-only.
The controller assigns the session, run, and grant IDs. The grant binds those
identities, the configured agent UID and principal, the exact proposal scope,
and expiry. The `local-requester` policy value is a compatibility fixture.
Authenticated human grant issuance, cancellation, and durable records remain
separate slices of the lifecycle in ADR-0001.

The client verifies the Control Plane peer before sending data. The Control
Plane verifies the agent peer on the same connection before reading data.
Stage 4.2 uses the agent-to-Control Plane link through a separate entry point.
Both Stage 4.1 handshakes retain their public interfaces and wire frames.

Each connection carries one version-2 proposal and one verdict. The request
starts with `AAO 02 01` in which the last two bytes are binary, followed by the
UTF-8 JSON representation of the existing strict health proposal. The
512-byte request bound includes the header. The reply starts with `AAO 02 02`
and contains one byte, `01` for proposal admission or `00` for denial. Both
sides require EOF to finish their frame. Extra authority fields, duplicate
keys, malformed or oversized frames, and unsupported proposals close the
exchange. A well-formed proposal with a failed scope, time, or policy check
receives a generic denial. A verified peer, a matching live grant, and an
explicit `ALLOW` from the existing policy evaluator are all required.

## Time, reuse, and evidence

Every accepted connection occupies one of 16 session slots, including wrong
peers, malformed input, and disconnects. The session handles one connection at
a time. An idle accept ends the session after ten seconds. A connection has
the Stage 4.1 one-second connect and two-second exchange limits. Identical
proposals may be admitted again on distinct connections while the grant
matches, remains live, and session slots remain. Copying a frame conveys no
authority by itself. The slice makes no cross-connection replay prevention
claim. A new session starts without a grant unless the trusted fixture
explicitly initializes one.

The grant lasts at most 15 minutes. Either the wall expiry or the
`CLOCK_BOOTTIME` deadline ends authority at equality, with no expiry grace.
Backward motion or a difference greater than one second between wall and
elapsed progress fails the session closed. The controller compares with
both the first and most recent samples. Unavailable clocks block admission.
A positive verdict requires a fresh time check after policy evaluation and
again before sending. The deadlines are cooperative.

The Control Plane's bounded in-memory journal records one admission or
denial decision per processed connection. Events carry fixed reasons,
server-generated correlation, and verified or server-owned identities where
available. They contain no raw payload or caller-supplied identity. A positive
reply requires successful recording. The record describes the decision at
evaluation time, independent of reply delivery. It carries no tool result
or execution claim. The trusted fixture can capture the returned journal.

## Acceptance gates

Run the deterministic proposal-admission tests and the existing Stage 2/3 and
Stage 4.1 regressions. The tests cover missing and mismatched grants, scoped
policy denial, expiry and clock errors, framing, the accepted-connection
budget, restart, and audit failure. Same-UID tests exercise verification and
exchange behavior. Native security acceptance requires a separately approved
distinct-UID run covering the new exchange and both original Stage 4.1 links.

The implementation scope is this contract, the existing boundary module,
`adaptive_agentops/stage4_boundary/delegation.py`, and
`tests/test_stage4_delegation.py`. Independent security review precedes commit
or push. Production remains NO-GO.
