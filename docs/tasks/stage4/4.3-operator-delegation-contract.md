## Authority and state

The trusted launcher supplies distinct non-root agent, Control Plane, target
and operator UIDs. It supplies a frozen operator UID-to-principal and role
map. For this slice exactly one mapped requester represents the existing
PDP principal `local-requester`. Approver-only mappings may connect when
configured for filesystem reachability and have no lifecycle permissions.
Issue, inspect, and revoke each require the requester role and are restricted
to that grantor's own grant. Groups control reachability. Connected Linux
`SO_PEERCRED` supplies identity, and only the server's map supplies roles.
The client verifies the Control Plane before sending. Only an authenticated
mapped peer reaches the protocol parser. A separate Control Plane-owned
operator directory and access GID keep its socket outside the agent link.

The controller starts an empty session with new session and run identifiers.
The requester can issue one grant during the entire session for 1 to 900
seconds. Each issuance re-evaluates the existing PDP for the fixed proposal.
The controller assigns the grant ID and binds the authenticated grantor,
configured agent UID and principal, controller session and run, and exact
`mock.get_health` / `demo-api` / `local-mock` scope. There is no grant field
in an agent proposal. Configuration and the deployed PDP are fixed for the
service session. Every admission re-evaluates the PDP and requires an explicit
ALLOW in addition to the verified peer, scope and live grant. This returns
an informational proposal verdict. Neither a grant nor a verdict authorizes
a health read, target traffic, pending action, approval, or dispatch.

A grant progresses from issued/active to elapsed or revoked. Either clock
reaching its deadline expires the grant at equality. Backward/divergent
clocks or unavailable time close the session; neither expiry nor revocation
can be undone. Inspect displays the own grant's state, identifiers, agent UID and wall
deadline, along with the fixed scope known to the client. Revoke requires
the exact grant ID and succeeds only while active. A new controller session
starts empty, assigns new identifiers, and never recovers old authority.
IDs are correlation values. There is one in-memory grant and bounded volatile
evidence. Durable state, cross-process ownership of durable databases,
persistent session invalidation, and the full issuance lifecycle are later
work. Host administrator compromise, MFA, and hostile same-UID processes are
outside this local guarantee.

## Transport and concurrent operations

The operator protocol uses a separate UNIX socket and version 3 binary
frames, with exact lengths and EOF. An issue request carries only a
two-byte lifetime; inspect carries no data; revoke carries a sixteen-byte
UUID. Identity, roles, principal, scope and executable commands cannot
be encoded in these frames. A response carries either a generic denial
or the current grant's identifiers, state, agent UID and original wall deadline.
Stage 4.2 agent frames and Stage 4.1 handshakes retain their formats.

A single controller thread owns both listeners, grants, and journals. It
processes one verified or rejected connection at a time across both links.
Pending connections have no authority. Each link has a backlog of one
and at most 16 accepts per session, including malformed, unauthorized and
disconnected peers. Hitting either cap or ten seconds of idle waiting closes
both listeners. A connection has a one-second connect bound and two-second
exchange bound. Socket deadlines are cooperative; trusted synchronous PDP
and journal code are in the service's execution assumptions.

Revoke linearizes when the controller installs the revoked state, after
its evidence is recorded. Admission linearizes at the final validity check
under exclusive service ownership immediately before the bounded verdict
send. Revoke ordered first prevents a positive verdict. Admission ordered
first may deliver a reply that a client reads after revocation. Cancellation
does not recall already committed reply bytes. Network I/O can fail after a
state change; a lost operator reply does not undo issue or revoke, and an
authorized inspect can recover state within the same live session.

## Audit and failure semantics

Record operator decisions with generated event ID, server session, verified
UID and grant ID when appropriate, fixed method/result, and no input bytes
or caller identity claims. Record admission decisions as in Stage 4.2.
An operator grant transition requires successful recording before installing
new authority or replying. A positive admission requires recording before
its final validity check. Journal failure stops both listeners and destroys
session authority. Clock failure closes both listeners. Protocol/peer errors
consume bounded connection slots. Journals describe decisions, not reply
delivery, durable evidence, or target effects. Trusted launch code may
capture the bounded journals.
