## Scope

Evaluate the existing synthetic projector and diagnostic formatter.
Use the existing Python and pytest environment. The proposed allowlist
is this contract, `docs/campaigns/stage5-progress.md`,
`evaluations/stage5_deterministic_cases.json`, and
`tests/test_stage53_deterministic_evaluation.py`. The scored runner
is a pytest test module. It may read only the repository's synthetic
evaluation artifacts as input. Product code, existing tests and the
regression manifest are outside the implementation allowlist. Escalate
any product defect through its own reviewed change.

Excluded capabilities include live storage or snapshot reads, sockets or
IPC, runtime instrumentation, mutations, retry or execution decisions,
new authority, dependencies, paid resources and native dispatch.
[Security rules](../../../SECURITY.md)

## Regression and new evaluation populations

`3674b2b94b828084d6a47bc7136e1d8272bd9caef058cdebb2fc168b48c193ab`.
Keep these bytes and expectations intact. Report the regression suite
separately. Its cases and existing boundary tests establish prior coverage
and contribute zero cases to the new denominator.

Create **16 new synthetic cases**, four in each family below. Novelty
requires a new evidence interaction or boundary assertion relative to both
the v5 corpus and existing tests. Renamed cases, changed IDs, alternate
whitespace and repeated execution contribute zero new cases. Record the
new interaction and nearest existing case or test in the freeze review.

## Freeze and reproducibility

Commit a separate dataset version with stable case IDs, family, synthetic
authorship/provenance and exact stimulus. Represent malformed bytes
losslessly. For unchecked objects, freeze named, allowlisted constructors
and their literal parameters, without executable content in the dataset.
Freeze expected classification, relevant source facts and provenance,
and exact diagnostic bytes or constant error behavior. Formatter-only
cases explicitly exempt classification and projector provenance. List
every assertion applicable to each case.

Before any scored execution, hash the exact manifest bytes with SHA-256
and pin the version, digest, counts and reviewed oracle in the test/checkpoint.
The independent reviewer checks novelty, coverage, labels and digest
without using projector output as an oracle. Scoring checks the digest
before executing any case. Corrections to the oracle require a new reviewed
version with the prior digest and result preserved. A disagreeing result
never authorizes relabeling. Record the runner revision, Python version and
repeat count. Synthetic fixtures provide deterministic contract evidence.

## Scoring and security gates

Run every frozen case twice with independent input construction and compare
complete normalized projector results and exact formatter outputs where
applicable. A case passes only if every applicable expectation passes.
Report exact classifications over the number of classification cases,
provenance checks over provenance-applicable cases, and full passes out
of 16 over the new corpus. Report per-family results out of four, failed
IDs and check categories. Repeats do not increase denominators. Skipped
or errored cases fail the run. Require 16/16 and a green full suite.

Count critical violations separately and fail on any one. Critical checks
include false effect or no-send certainty, loss of uncertainty, mislabeled
evidence attribution, any retry or authority implication, unexpected
diagnostic fields or sensitive canaries, input mutation, nondeterminism,
and filesystem, logger, network or database calls by the units under
test. Assert output allowlists, bounds and noninterference directly.
Emit only reviewed synthetic case IDs, fixed check categories and counts
in failure summaries. Avoid emitting raw fixture data, unchecked values
or exception text.

focused and full local tests, obtain independent exact-diff review, and
verify ordinary CI and the merged tree. Record results and outstanding
